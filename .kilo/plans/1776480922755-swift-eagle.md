# Fix Dashboard Stats Showing Zero

## Problem
Dashboard stats display **0** for all metrics even though the backend API returns correct data (as confirmed by logs and direct API call).

**Backend log:**
```
Dashboard stats: Projects=3, Drafts=0, Messages=4, Unread=2
```

**Actual API JSON response:**
```json
{
  "totalProjects": 3,
  "draftProjects": 0,
  "totalMessages": 4,
  "unreadMessages": 2,
  "repliedMessages": 1,
  "totalSkills": 16,
  "skillCategories": 4,
  "profileViews": 0,
  "recentProjects": [...]
}
```

## Root Cause
**Property name casing mismatch** between backend JSON and frontend TypeScript interface:

- **Backend** → .NET's `System.Text.Json` serializes properties as **camelCase** by default
- **Frontend** → `DashboardStats` interface defines properties in **PascalCase**
  ```typescript
  export interface DashboardStats {
    TotalProjects: number;   // ❌ expects "TotalProjects"
    DraftProjects: number;   // ❌ expects "DraftProjects"
    ...
  }
  ```

When Angular's `HttpClient` deserializes the camelCase JSON into the PascalCase-typed interface, **no properties match**, so all values are `undefined`. The template uses `stats?.TotalProjects || 0` → `undefined || 0` → displays **0**.

## Solution
Change the `DashboardStats` interface to use **camelCase** property names that match the actual JSON response.

### File to modify:
**`frontend/src/app/core/models/portfolio.models.ts`** (lines 165-175)

### Change:
```typescript
// BEFORE (incorrect - PascalCase)
export interface DashboardStats {
  TotalProjects: number;
  DraftProjects: number;
  TotalMessages: number;
  UnreadMessages: number;
  TotalSkills: number;
  SkillCategories: number;
  ProfileViews: number;
  RecentProjects: { ... }[];
}

// AFTER (correct - camelCase)
export interface DashboardStats {
  totalProjects: number;
  draftProjects: number;
  totalMessages: number;
  unreadMessages: number;
  totalSkills: number;
  skillCategories: number;
  profileViews: number;
  recentProjects: { id: number; title: string; description: string; stack: string; status: string; image: string }[];
}
```

### Also update dashboard template to use camelCase:
**`frontend/src/app/admin/pages/dashboard/dashboard.component.html`**

Change all `stats?.Total...`, `stats?.Draft...`, `stats?.TotalMessages`, `stats?.UnreadMessages`, `stats?.TotalSkills`, `stats?.SkillCategories` → to camelCase equivalents matching the JSON (totalProjects, draftProjects, totalMessages, unreadMessages, totalSkills, skillCategories).

Current template lines to change:
- Line 20: `{{ stats?.TotalProjects || 0 }}` → `{{ stats?.totalProjects || 0 }}`
- Line 23: `{{ stats?.DraftProjects || 0 }}` → `{{ stats?.draftProjects || 0 }}`
- Line 32: `{{ stats?.TotalMessages || 0 }}` → `{{ stats?.totalMessages || 0 }}`
- Line 35: `{{ stats?.UnreadMessages }}` → `{{ stats?.unreadMessages }}`
- Line 44: `{{ stats?.TotalSkills || 0 }}` → `{{ stats?.totalSkills || 0 }}`
- Line 47: `{{ stats?.SkillCategories || 0 }}` → `{{ stats?.skillCategories || 0 }}`

## Alternative Solution (if you want to keep PascalCase in TypeScript)
Configure the .NET backend to use PascalCase JSON by adding to `Program.cs`:
```csharp
builder.Services.AddControllers()
    .AddJsonOptions(options =>
        options.JsonSerializerOptions.PropertyNamingPolicy = null);
```

But this would require changing all other frontend interfaces to PascalCase as well (they're currently camelCase). **Recommended: fix the frontend to use camelCase** (standard for JavaScript/TypeScript).

## Expected Result After Fix
Dashboard will display:
- Projects: **3**
- Drafts: **0**
- Messages: **4**
- Unread: **2**
- Skills: **16**
- Skill Categories: **4**
